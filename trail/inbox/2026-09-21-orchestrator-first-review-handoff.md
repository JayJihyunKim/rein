# 2026-09-21 — 메인 세션 지휘 기본화 구현 1/4: 워커 리뷰 이관 예외 명문화

## 한 것

계획 `docs/plans/2026-09-21-orchestrator-first-default.md` 의 선행 단계(Phase 0 / Task 0.1)를 메인 세션이 직접 편집했다 — 서브에이전트 dispatch 없음.

- `AGENTS.md` §5-1: "워커 실행 시 리뷰 이관" 예외 불릿 1개. 지휘자(부모)가 웨이브 끝에서 리뷰·증거 발급을 하는 흐름에서 워커로 실행된 에이전트는 자체 코드 리뷰와 수정 후 재리뷰를 하지 않는다 — 면제가 아니라 부모로 이관, 커밋 시점 리뷰 요구는 그대로.
- `plugins/rein-core/agents/feature-builder.md`·`feature-builder-fix.md`·`feature-builder-refactor.md`: 완료 기준의 코드 리뷰·수정 후 재리뷰·보안 리뷰 세 줄 각각에 "단독 실행 시 직접 수행 / 워커 dispatch 시 부모가 웨이브 barrier 에서 수행". 체크리스트 아래 설명 문장에 워커 dispatch 의 판별 신호(부모가 dispatch 프롬프트로 작업 단위·쓰기 범위·금지목록을 전달한 경우)와 "그런 전달이 없으면 단독 실행으로 본다" 를 넣었다.
- 지휘자 에이전트 정의와 워커 변형 정의는 무변경.

## 검증

- 계획 Task 0.1 확인 명령 전부 충족(예외 불릿 한 줄에 워커·재리뷰·이관, 세 파일 × 세 의무), Builder 변형 고정 테스트·규칙 스위트·에이전트 스위트·플러그인 정적 검사 회귀 없음.
- 코드 리뷰 3회: 통과(92초) → 수정 필요(311초) → 통과(591초).
  - 첫 통과 뒤 보안 검토의 낮은 등급 의견(판별 신호 구절)을 반영하느라 다시 받았다.
  - 두 번째의 유일한 지적은 중간 등급 "범위 항목 ID 문자열 자체에 방향·상황이 없다" — 구현 검사는 전부 통과. 같은 ID 를 첫 확인은 문제없다고 판정했었다. 개명하지 않고 후속 요청서 양식의 "반박" 칸으로 대응: 저장소 규칙(`design-plan-coverage.md` §1.2)은 세 요소를 ID 의 **서술부**에 요구하며 차단은 별도 단계에 위임한다. 세 번째 확인에서 검토자가 반박을 타당하다고 판단, 통과.
- 보안 리뷰: 통과, 차단급 없음. 낮은 등급 참고 1건(위 판별 신호)은 반영. 변경분이 전부 문서라 보안 증거 발급기는 "증명할 민감 대상 없음" 으로 정상 스킵(종료 코드 0).

## 관찰 (다음 단위에 쓸 것)

- 코드 리뷰 요청서는 증거 블록에 축 표식 두 개(정적 검사 축·테스트 축, 서로 다른 블록, 둘 다 종료 코드 0)와 블록 밖 `diff_self_review:` 한 줄이 필수다. 빠지면 리뷰 시작 전에 거부된다(비용 없음). 문서만 바뀐 단위에서는 플러그인 정적 검사(`scripts/rein-check-plugin-drift.py`)를 정적 검사 축으로 썼다.
- 세 파일 내용을 바꾼 뒤에도 통과 증거의 검토 대상 지문이 첫 통과 때와 같았다 — 문서 파일은 코드 리뷰 지문의 대상이 아닌 것으로 보인다. 그렇다면 두 번째·세 번째 확인(합계 약 15분)은 커밋 게이트 관점에서는 필요 없었다. 문서만 바뀌는 마지막 단위(8월 잠긴 설계 문서 주석)에서는 먼저 검토 대상 지문을 출력해 보고 재검토 필요 여부를 정할 것.
- 같은 입력에 대한 검토자 판정이 회차마다 갈릴 수 있다(ID 형식 지적). 범위 밖 문서를 고치라는 지적은 개명·재작성으로 받지 말고 근거를 붙여 반박한다.

- 오케스트레이션: 1개 하위 작업(병렬 N) — 단일 처리 시: "분해 불필요(계획이 메인 세션 직접 편집으로 지정한 선행 단계)"
