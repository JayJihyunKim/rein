## 배경 — 회고 진단보다 한 단계 더 정확한 원인

회고는 리뷰어의 "심도 표류"(O6·O12)와 "회차 상한 산문 지시의 무력화"(O11·O13)를 원인으로 봤다. 코드 실측 결과 둘 다 **구현에 원인이 있었다**.

### 원인 1 — 문서 리뷰가 코드 리뷰 지시문을 그대로 받는다

`rein-codex-review.sh` 의 `build_envelope()` 에는 리뷰 모드 분기가 **없다**. 문서 리뷰(`spec-review`)에서도 코드 리뷰와 동일한 4개 슬롯이 방출된다:

| 슬롯 | 문서 리뷰에서의 문제 |
|---|---|
| `1. Code defects and regressions — (look-ahead, 타입, 경계, resource leak 등)` | 문서에 코드가 없는데 자원 누수를 찾으라고 지시 |
| `2. Design Alignment` | 문서 리뷰에선 covers/scope_items 가 N/A 로 가므로 대부분 공회전 |
| `3. Test Alignment` | 문서에 테스트 함수가 없음 |
| `4. Claim Audit` | 유효 (문서의 수치 주장 검증) |

→ O12 에서 리뷰어가 계획서를 놓고 파일 핸들 수명주기·닫기 실패·이중 닫기를 지적한 것은 **지시받은 그대로 수행한 결과**다. 리뷰어 판정 표류가 아니라 rein 의 지시 결함이다.

여기에 `SKILL.md` §6.7 이 문서 리뷰에서 요청서 사전검사·증거 계약을 통째로 건너뛰므로, **판정 축은 부재한데 코드 리뷰 지시만 남은** 상태가 된다. O1(구현 세부의 문서 침투)·O2(재진술)·O6(일반론 수입)·O12 가 여기서 파생된다.

### 원인 2 — 회차 개념이 코드에 존재하지 않는다

`SKILL.md` §3 은 "stamp 의 `review_round` 필드에 현재 회차를 기록한다"고 서술하지만, 실제 stamp 작성부(`write_code_review_stamp`)가 쓰는 12개 필드에 `review_round` 는 **없다**. 래퍼 2,470줄 전체에 회차 카운터·상한이 부재하다.

→ 회차 상한이 오직 산문 지시로만 존재했고, 실측에서 두 번 무력화됐다(13회차 무보고 연속 실행 / 종결 명령 후 5회차 폭주). **산문 지침을 한 줄 더 쓰는 처방은 이미 두 번 반증됐으므로 채택하지 않는다.**

## 범위

### 1. 문서 리뷰 판정 계약 (A-1)

`build_envelope()` 에 리뷰 모드 분기를 신설한다.

- **코드 리뷰 모드**: 현행 슬롯을 **바이트 동일**로 유지 (기존 하위호환 패턴 준수 — 회귀 0).
- **문서 리뷰 모드**: 슬롯 세트를 문서 계층에 맞게 교체한다.
  - 코드 결함 슬롯·테스트 정합 슬롯은 **방출하지 않는다**.
  - 결정 건전성 슬롯 — 채택 결정·기각 대안의 근거 유무, 문서 내 상충 결정.
  - 범위·추적성 슬롯 — Scope ID 가 측정 가능한 계약인가, 상위 문서(브레인스톰/설계)와 정합하는가, 결정해야 할 변수가 누락됐는가.
  - 주장 감사 슬롯 — 유지 (문서의 수치·완료 주장 검증은 문서 리뷰에서도 유효).
- **판정 규율 3종을 envelope 에 실제 삽입**한다 (규칙 문서에만 쓰지 않는다):
  - (i) **심도-계층**: 구현 수준 결함(오류 경로·자원 수명주기·버퍼링 방식·자료구조 선택)은 판정(verdict)에 반영하지 않고 "구현 단계 이관" 참고사항으로 분류한다. 문서 판정 축은 결정·범위·추적성이다.
  - (ii) **결함 족 일괄 열거**: 같은 성격의 지적은 적용 대상 전체를 이번 회차에 한 번에 열거한다. 입력·대상별로 쪼개 회차를 늘리는 것을 금지한다.
  - (iii) **근거 출처 분리**: 저장소에 존재하지 않는 일반 규칙(임의의 줄 수 상한 등)을 근거로 반려 판정하지 않는다. 저장소 계약 위반과 일반론 참고사항을 분리 표기한다.

기존 선례를 따른다 — 래퍼는 이미 `TIER2_DESIGN_ADVISORY_NOTE` 로 "이 항목 단독으로 판정을 승격하지 마라"는 지시문을 envelope 에 삽입하고 있다. 같은 방식·같은 자리다.

### 2. 리뷰 회차 예산 코드 강제 (A-2)

- **사이클 키**: 문서 리뷰는 리뷰 대상 문서 경로(`SPEC_REVIEW_SUBJECT`), 코드 리뷰는 활성 작업 기준서 slug(stamp 의 `cycle` 과 동일 산출). 기준서 부재 시 고정 sentinel.
- **카운터 저장**: `trail/dod/.review-rounds/<키 해시>` 파일. 키 원문·현재 회차·적용 상한·갱신 시각·연장 이력을 기록한다.
- **기본 상한**: **5회차** (양 모드 공통). 근거 — 기존 "3회차에도 High 잔존 시 사람 에스컬레이션" 규칙에 2회 여유를 둔 값이며, 실측(문서 41회·26회)과의 격차가 이번 처방의 절감분이다.

- **연장 계약** (사용자 결정): 호출자가 프롬프트 마커로 상한을 선언하면 그 값을 적용한다. 기존 `[EFFORT:]` 마커 파싱 패턴을 따른다.

- **계수 시점**: codex 실행 직전 1회 증가. 사전검사에서 거부된 호출은 계수하지 않는다(요청서 형식 반려가 예산을 잠식하지 않게).
