# 보안 통과 기록의 발급 주체 — 지휘자(부모)가 발급한다

- 날짜: 2026-09-21
- 결정자: 사용자 ("오케스트레이터가 하면 되는거 아니야?")
- 대상: `plugins/rein-core/agents/orchestrator.md` 의 워커 금지목록, `plugins/rein-core/agents/security-reviewer.md` §6, `plugins/rein-core/rules/orchestrator-first.md` §4, `plugins/rein-core/skills/parallel-execute/SKILL.md` 의 부모 통합 절, 작업 순서표 6단계

## 배경

두 문서가 정면으로 부딪혀 있었다 — 워커 금지목록은 "보안 워커를 포함한 모든 워커는 리뷰·보안 통과 기록을 발급하지 않는다(부모 소유)", 보안 리뷰어 정의는 "통과 시 검토자가 직접 발급한다". v2.0.0 배포 이래 있던 모순이고 설계 `docs/specs/2026-09-10-orchestrator-first-default.md` §8 항목 1 이 별도 작업으로 분리해 두었다. 지휘 기본화 구현(2026-09-21)에서 새 규칙 본문이 그 금지목록을 기본 경로의 기준으로 가리키게 되면서, 웨이브 1 보안 검토자가 중간 등급으로 다시 짚었다.

## 결정

**지휘자(부모 — 기본 경로에서는 메인 세션)가 발급한다.** 금지목록 쪽이 맞는 방향이다. 보안 검토자는 판정과 근거를 반환하고, 통과 기록은 부모가 남긴다.

## 구현할 때 지켜야 할 것 (검토자가 짚은 위험)

- 통과 기록은 **검토 시작 시점의 내용**에 묶여야 한다. 부모가 검토가 끝난 뒤에 지문을 잡아 발급하면 검토하지 않은 내용까지 통과 처리될 수 있다.
- 그래서 순서는: 부모가 (스테이징 후) 지문을 먼저 잡는다 → 그 값을 검토자에게 넘긴다 → 검토자는 자신이 본 내용의 지문이 그 값과 같은지 확인하고 판정과 함께 돌려준다 → 부모가 **그 값으로** 발급한다. 발급 직전 현재 지문이 같은 값인지 다시 확인한다.
- 검토자의 반환 형식(판정·지적·검토한 지문)을 정해야 한다 — 설계 §8 항목 1 이 "워커→부모 반환 스키마 설계가 별도로 필요" 라고 적은 부분.
- 단독 실행(지휘 흐름 밖에서 보안 리뷰어만 부른 경우)의 발급 주체도 같이 정리한다 — 1/4 단위에서 Builder 정의에 넣은 "단독 실행 / 워커 dispatch" 구분과 같은 축.

## 상태

결정만 기록. 구현은 별도 작업(설계 → 계획 → 구현) — v2.1.2 릴리스에는 넣지 않는다. 그때까지는 지금의 절차(검토자가 검토 시작 시점 지문에 묶어 직접 발급)를 쓴다.
