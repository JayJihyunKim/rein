## Task 6.1 본작업 구조 결정 (2026-08-18, 사용자 결정 — 계획서 문구와의 차이 기록)

3. **잠재 지뢰 기록 (D4, 미래형)** — v2 보안 capability 는 "민감 변경 digest 없음 = 보수적 미충족"

   통상 코드 커밋(자격증명 파일 무관)이 영구 차단될 수 있는 구조적 충돌. **오늘은 발급 경로 자체가
   없어 잠재 상태** — 발급 경로를 여는 작업의 선행 조건으로 이 충돌 해소를 명시(백로그 승격).

## 활성 작업 축 보안 봉합 2건 (2026-08-19, 검토 실증)
- **0x1F 구분자 충돌** (High) — 성능 수리가 file_path/tool_name 을 0x1F join 단일 추출로 뽑고 `read` 로
  분리하는데, file_path 에 0x1F 가 섞이면 확장자 앞에서 절단 → 비소스 오분류 → exit 0 무음 통과로
  판정 체인 전체 우회. 수리: `read` 전 구분자 개수 검사(정확히 1 아니면 fail-closed exit 2). 회귀 sec1.
- **LF read 절단** (High, 재검토 발견) — 위 개수 검사를 통과해도 bash `read` 가 IFS 무관하게 첫 개행에서
  레코드를 끊어 file_path 의 LF 앞에서 FILE_PATH 절단 → 동일 우회. 수리: LF 를 하나 더 차단하는 열거
  대신 `read` 를 파라미터 확장 위치 분할로 교체(이미 검증된 단일 0x1F 기준) — 절단 클래스(LF·기타
  종결 후보) 통째 제거, 경로 안 LF 는 보존돼 실제 확장자로 정상 분류. 회귀 sec2 red→green.
- 보안 재재검토 PASS: 독립 재현·전 바이트 클래스 보존·훅 전역에서 동일 패턴 이 파일 단일 확인.
