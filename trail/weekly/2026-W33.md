## 무엇이 문제였나

반입 검증이 설계서 요건대로 사적 경로를 거부하는데 **수집 단계에 그 규칙을 피할 축약이 아예 없었다**. 결과적으로 절대경로를 담은 레코드가 전량 거부되어 조용히 사라졌다.

실측 (수리 전, 기록 308건): 편집 계열 훅 레코드 9건이 전부 빈 값이거나 수동 테스트로 넣은 상대경로 — **실제 편집 파일 경로 레코드 0건**. 이 저장소만의 문제가 아니라 홈 아래에 프로젝트를 두는 모든 사용자 + CI 러너(`/home/runner/…`)가 해당하고, 명령 기록도 절대경로가 섞이면 같이 유실된다.

검증 규칙 자체는 옳았다(사용자명 유출 방지). 빠진 건 반대편이었다.

## 무엇을 했나

**설계**: 규칙을 `rein/shadow/paths.py` 로 분리해 **검출(반입 검증)과 정규화(수집)가 같은 정의를 소비**하게 했다. 규칙이 두 곳에 살면 한쪽만 고쳐져 갈라지는 결함 클래스를 Phase 2 에서 이미 4회 반복했다 — 같은 실수를 구조로 막았다.

**동작** (사용자 결정): 프로젝트 안 경로는 루트 기준 상대경로, 밖의 홈 경로는 사용자명 세그먼트만 치환. 대조 신호(어떤 파일을 건드렸는가)를 최대한 보존하는 쪽.

**추가 발견**: 수리 후 디스크 검사에서 두 번째 유출을 찾았다 — 도구 작업 디렉토리가 프로젝트 절대경로의 슬래시를 하이픈으로 인코딩해(`/tmp/x/-Users-<name>-<proj>/…`) 슬래시 기준 규칙을 통째로 비껴갔다. 같은 라운드에서 봉합.

## 리뷰가 잡은 결함 (전부 실측 재현 후 봉합)

코드 리뷰 7회차 · 보안 리뷰 3회차. **첫 판정 이후 매 회차 실질 결함이 나왔다.**

1. **[High] mapping key 가 정화·검증을 둘 다 우회** — 값만 훑는 구조라 `{"/Users/alice/x": True}` 가 사용자명을 남긴 채 최후 관문까지 통과.
2. **[High] 거부 사유가 민감한 key 원문을 되뿜음** — 2회에 걸쳐 접근을 바꿨다. 처음엔 "key 유래 라벨만 익명화" 했는데, 위반이 **값** 쪽일 때 그 라벨의 **조상 세그먼트**로 여전히 샜다. 최종적으로 **라벨 생성을 데이터와 완전히 분리**(스키마 최상위 key 만 이름, 나머지는 위치 표기)해서 "검출기가 잡는 만큼만 안전" 이라는 결합 자체를 끊었다. 부수 효과로 라벨에 대한 정규식 실행 표면이 통째로 사라졌다.
3. **[Medium] 경계 3종** — 하이픈 규칙이 명령 옵션(`echo -Users-alice-feature`)을 삼킴 / 루트 접두 제거의 왼쪽 경계 부재(`/tmp/prefix<root>/a` → `/tmp/prefixa`) / 경계를 "경로 문자" 열거로 잡아 `+`·`@`·`=` 가 빠짐.
4. **[Medium] 경로 끝 슬래시가 값을 소거** — `cd <root>/ && …` 가 `cd  && …` 로. 모듈이 스스로 선언한 "빈 문자열은 안 만든다" 불변식을 깨고 있었다.
5. **[Medium] oversized 라벨의 길이 관문 순서** — 거대한 key 원문이 예외 메시지로 반사.
6. **[Low] 최상위 key 모양 검사 우회** — 영숫자+밑줄 32자 이하 secret(토큰·액세스 키 ID)이 통과. 스키마 key 집합 검사로 교체.
7. **[Info] 필드 커버리지 불일치** — 두 필드만 정화를 건너뛰어 "모든 문자열 필드" 주장과 구현이 어긋남.

## 방법론에서 반복 확인된 것

- **경계는 열거로 닫히지 않는다**: POSIX 파일명은 `/`·NUL 외 전부 허용이라 "경로 문자" 열거는 원리적으로 미완결. 방향을 뒤집어 **구분자 화이트리스트**로 판정하고, 모르는 문자를 만나면 자르지 않는다. 이 보수적 실패가 안전한 이유는 사용자명 제거를 그 다음 단계(홈 축약)가 책임지기 때문 — **실패 방향을 설계로 배치**했다.
- **유출 방어를 검출 신호에 결합하지 마라**: 라벨 안전성을 검출기에 의존시키면 검출기의 사각지대를 그대로 물려받는다. 데이터와 분리하면 검출 규칙이 무엇을 놓치든 라벨은 안전하다.
- **오탐과의 trade 는 명시적으로**: 보안 리뷰어가 물결표 규칙 확대를 제안했다가, 산문(`~ish`·`~about`)을 홈 경로로 오인한다는 실측을 보고 **스스로 철회**했다. 수용 한계 3종을 근거와 함께 문서에 남겼다.
